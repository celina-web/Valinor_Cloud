     Plan: refactor de autenticación/autorización a Passport + JWT (stateless)

     Contexto

     Hoy TurnoFlex autentica con express-session (cookie connect.sid + store en
     memoria del servidor). requiereLogin lee req.session.usuarioId, vuelve a
     buscar al usuario en Mongo y destruye la sesión si está
     desactivado/vencido/eliminado. El login compara contraseñas en texto plano.
     Se quiere pasar a Passport + JWT stateless, sin perder ninguna
     funcionalidad (vistas Pug con nav por permisos, API JSON, control por
     contexto, auditoría, revocación), documentar todo en
     docs/refactor-passport-jwt.md y depurar el README.

     Decisiones tomadas con el usuario:
     - Transporte: el JWT viaja en cookie httpOnly (para el navegador y las
       vistas Pug) y se acepta Authorization: Bearer (Postman / clientes
       externos). El login devuelve el token también en el JSON.
     - Login: passport-local + contraseñas hasheadas con bcryptjs (JS puro, sin
       compilación nativa en node:22-alpine).
     - Revocación: el verify de passport-jwt sigue leyendo el usuario de Mongo
       (se mantiene SESION_REVOCADA) + campo tokenVersion en Usuario para
       invalidar tokens en logout y cambio de contraseña. No se guardan sesiones
       en el servidor.

     Paso 0: línea base (antes de tocar código)

     - Levantar Mongo (docker compose up -d mongo o local), npm install, npm run
       seed, npm start.
     - Correr la colección de Postman con npx newman run 
       docs/TurnoFlex.postman_collection.json y guardar el resultado como
       referencia de comportamiento actual.

     Cambios

     1. Dependencias y entorno

     - package.json: agregar passport, passport-local, passport-jwt,
       jsonwebtoken, bcryptjs, cookie-parser; quitar express-session.
     - .env.example: reemplazar SESSION_SECRET / SESSION_MINUTOS por JWT_SECRET
       y JWT_MINUTOS (default 30).
     - docker-compose.yml no cambia (toma todo del .env).

     2. Modelo src/models/Usuario.js

     - Nuevo campo tokenVersion: { type: Number, default: 0 }; excluirlo en el
       toJSON junto con password.
     - pre("save"): si isModified("password") → hashear con bcrypt (la
       validación minlength: 6 corre antes del hook, así que valida la
       contraseña en claro). Si además !isNew → tokenVersion += 1 (invalida
       tokens viejos al cambiar contraseña).
     - Método compararPassword(texto) con bcrypt.compare.
     - estaHabilitado() se mantiene igual.
     - crearUsuario / actualizarUsuario (src/controllers/usuariosController.js)
       y src/seed.js ya usan create / save, así que el hash se aplica solo;
       describirCambios se calcula antes del save y no lista tokenVersion.

     3. Nuevo src/helpers/token.js

     - firmarToken(usuario): jwt.sign({ sub: id, usuario: usuario.usuario, ver: 
       usuario.tokenVersion }, JWT_SECRET, { expiresIn: JWT_MINUTOS*60, 
       algorithm: "HS256" }).
     - enviarTokenEnCookie(res, token): cookie token, httpOnly, sameSite: 
       "strict", secure si NODE_ENV === "production", maxAge = JWT_MINUTOS.
     - borrarCookieToken(res).
     - Constantes JWT_SECRET (fallback de desarrollo, como hoy con la sesión) y
       JWT_MINUTOS leídas del entorno en un solo lugar.

     4. Nuevo src/config/passport.js (estrategias)

     - LocalStrategy (usernameField: "usuario", passReqToCallback: true):
       normaliza el usuario (trim + lowercase), busca con .select("+password"),
       compararPassword. Devuelve done(null, false, { status, error, usuario? })
       para credenciales inválidas (401) o usuario deshabilitado (403), para
       que el controlador audite LOGIN_FALLIDO igual que hoy.
     - JwtStrategy: jwtFromRequest = 
       ExtractJwt.fromExtractors([fromAuthHeaderAsBearerToken(), req => 
       req.cookies?.token]), algorithms: ["HS256"]. El verify busca
       Usuario.findById(payload.sub) y devuelve:
       - usuario válido → done(null, usuario);
       - eliminado / !estaHabilitado() → done(null, false, { revocado: true, 
         detalle, payload });
       - payload.ver !== usuario.tokenVersion → done(null, false, { mensaje: "Tu
         sesión fue cerrada" }).

     5. src/middlewares/auth.js

     - Helper autenticar(estrategia, req, res) que envuelve
       passport.authenticate(estrategia, { session: false }, cb) en una Promise,
       para que los middlewares sigan siendo async y Express 5 propague errores
       al errorHandler.
     - requiereLogin: usa autenticar("jwt"). Sin usuario → borrarCookieToken +
       responderSinSesion (401 JSON en /api, redirect a /login en vistas — se
       conserva esApi). Si info.revocado → auditar SESION_REVOCADA (con
       usuarioNombre tomado del payload). Token vencido → mensaje "Tu sesión
       expiró". Con usuario → setea req.usuario y res.locals (usuario, permisos,
       puede) exactamente como hoy.
     - Renovación deslizante (equivalente al rolling de la sesión): si el token
       vino por cookie y le queda menos de la mitad de vida, se firma uno nuevo
       y se reenvía la cookie. Así la expiración sigue siendo "por inactividad"
       en el navegador.
     - Nuevo usuarioOpcional: igual pero sin cortar la request (para /login).
     - requierePermiso no cambia. Se elimina destruirSesion.

     6. Login / logout (src/controllers/authController.js, 
     src/routes/api/authRoutes.js)

     - login: mantiene el 400 si faltan campos; luego autenticar("local"). Fallo
       → auditar LOGIN_FALLIDO y responder con el status/mensaje del info.
       Éxito → firmarToken, enviarTokenEnCookie, actualizar ultimoAcceso (con
       timestamps: false, como hoy), auditar LOGIN, responder { token, usuario, 
       nombre, rol }. Se elimina regenerarSesion.
     - logout: Usuario.updateOne({ _id }, { $inc: { tokenVersion: 1 } }, { 
       timestamps: false }), borrarCookieToken, auditar LOGOUT, 204. (Efecto
       documentado: cierra la sesión en todos los dispositivos de ese usuario.)
     - usuarioActual sin cambios.
     - usuariosController.actualizarUsuario: si el admin cambia su propia
       contraseña, reemitir el token en la cookie para que no lo eche.

     7. src/index.js y vistas

     - Quitar express-session; agregar cookieParser(),
       require("./config/passport") y app.use(passport.initialize()).
     - src/routes/vistasRoutes.js: router.get("/login", usuarioOpcional, 
       mostrarLogin).
     - src/controllers/vistasController.js: mostrarLogin usa req.usuario en
       lugar de req.session.usuarioId.
     - layout.pug, home.pug y los demás Pug no cambian (siguen leyendo
       res.locals).

     8. Front (src/public/js)

     - api.js y login.js funcionan sin cambios funcionales: fetch same-origin
       envía la cookie, el 401 sigue redirigiendo a /login y el logout ya llama
       a /api/auth/logout. Solo se ajusta el mensaje/comentario del 401 si hace
       falta. El token del JSON no se guarda en localStorage (a propósito, por
       XSS).

     9. Postman (docs/TurnoFlex.postman_collection.json)

     - Auth a nivel colección: Bearer {{token}}; variable token.
     - Tests de cada login: pm.collectionVariables.set("token", 
       pm.response.json().token) y verificar que exista token.
     - Revisar el orden: después de Logout el token queda invalidado
       (tokenVersion), así que la carpeta siguiente debe volver a hacer login
       (agregar request o ajustar orden). Actualizar la descripción (ya no habla
       de connect.sid).
     - Agregar casos: token inválido → 401, sin token → 401, token viejo después
       de logout → 401.

     10. Documentación

     - docs/refactor-passport-jwt.md (nuevo, en español rioplatense):
       motivación; comparación antes/después (sesión con estado vs JWT
       stateless); diagrama/flujo de login y de request autenticada; detalle
       archivo por archivo de los cambios; payload del token y configuración de
       la cookie; estrategia de revocación (lectura de usuario + tokenVersion) y
       sus límites; renovación deslizante; hashing de contraseñas y necesidad
       de re-correr npm run seed; consideraciones de seguridad (httpOnly,
       sameSite=strict como mitigación de CSRF, secure en producción, secreto en
       .env, algoritmo fijo); variables de entorno nuevas/eliminadas; cambios
       en Postman; cómo se verificó.
     - README.md — depurar y actualizar:
       - Intro: reemplazar "sesiones con express-session" por Passport (local +
         JWT) con contraseñas hasheadas.
       - Tabla de variables: JWT_SECRET, JWT_MINUTOS (quitar SESSION_*).
       - Estructura: agregar config/passport.js y helpers/token.js; auth.js
         describe requiereLogin (JWT), usuarioOpcional, requierePermiso;
         mencionar docs/refactor-passport-jwt.md y docs/Docker/.
       - "Cómo funciona": paso de autenticación con JWT (cookie o Bearer).
       - Modelos: usuarios con password hasheada y tokenVersion.
       - Buenas prácticas: reescribir "Revocación automática" (expiración del
         token + renovación, lectura del usuario por request, tokenVersion en

       - API REST: "requieren token" (401 sin token / token inválido), login
         devuelve { token, ... } y setea cookie, ejemplo de header

       - Bibliografía: quitar express-session; agregar Passport, passport-local,

     - docs/Docker/docker-readme.md: cambiar menciones a SESSION_SECRET /
